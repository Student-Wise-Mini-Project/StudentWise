# Lifecycle and Recurring Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the four gaps between a backend that is finished and a frontend that never grew the screens for it — the `+` bar's dead end, the missing recurring-bills UI, the missing close/delete for a group, and group creation that cannot suggest anybody.

**Architecture:** Four independent branches off `main`. Only one (`feat/close-groups`) touches the database; it adds `groups.archived_at` and one business rule, `group_service.require_open`, called explicitly at the top of each write service. The other three are frontend-only and follow the existing feature-folder shape — `features/<area>/api.ts` for hooks, a screen, and sheets built on the existing `Sheet` primitive.

**Tech Stack:** FastAPI + SQLAlchemy 2.0 sync + Alembic + pytest (backend); React 19 + TanStack Query v5 + Tailwind v4 + Vitest/Testing Library/MSW on happy-dom (frontend).

**Spec:** `docs/superpowers/specs/2026-09-12-lifecycle-and-recurring-design.md`

## Global Constraints

- Money is always `Decimal` / `NUMERIC(12,2)` on the backend and a **string** on the wire and in the client. Never `float`, never `number`. The client never divides money.
- One file per entity in every layer. `api/`, `services/`, `repositories/`, `models/`, `schemas/`.
- Services own the transaction and commit; repositories never call `db.commit()`.
- Raise from `core/errors.py`, never `HTTPException` directly.
- No native Postgres ENUM types — `enum_column(SomeEnum)` only.
- Every schema change gets an Alembic migration **in the same commit as the model**.
- Every new endpoint gets a test in `backend/tests/api/`.
- List endpoints return `Page[T]`, never a bare array. (No new list endpoints here.)
- **No user-visible string lives in a component.** Every one is a key in `frontend/src/i18n/messages/en/<area>.json` **and** `he/<area>.json`. Hebrew is gender-neutral: `החוב שלך` not `אתה חייב`; past-tense second person (`שילמת`, `הוספת`) is safe.
- **Only `frontend/src/styles/` may name a colour or typeface.** No hex, no `rgb(`, no `font-family`, no Tailwind arbitrary-colour class anywhere else.
- **No physical direction utilities.** `ms-`/`me-`, never `ml-`/`mr-`; `text-start`, never `text-left`.
- `frontend/src/api/schema.d.ts` is generated. Never hand-edit. Run `npm run gen:api` with the backend up and commit the result.
- Three guard tests must pass: `test/guards/design-tokens.test.ts`, `test/guards/logical-props.test.ts`, `test/guards/no-bare-strings.test.ts`.
- Never push to `main`. Branch per part; PR per branch.

**Deviation from the spec's sequencing, deliberate:** the spec ordered these smallest-first (`picker`, `suggestions`, `close`, `recurring`). `feat/close-groups` moves to the front instead, because the picker filters closed groups and the group list sections them — building the picker first means editing it again a branch later. `feat/recurring-ui` stays last, as the spec intended.

In `backend/app/services/group_service.py`, after `require_owner`:

```python
def require_open(group: Group) -> None:
    """A closed group takes no new spending.

    Called explicitly at the top of each write service rather than wired as a
    dependency: `PATCH /expenses/{id}` resolves through `ExpenseForMember`, not
    `GroupMembership`, so no single dependency reaches every write. An explicit
    call is also greppable, which a dependency is not.
    """
    if not group.is_open:
        raise ConflictError("This group is closed")
```

and after `delete_group`:

```python
def close_group(db: Session, group: Group) -> Group:
    """End a trip. Deliberately allowed while balances are outstanding: real
    trips end with someone paying in cash, and a group that cannot be closed
    until the app agrees it is square is a group nobody can ever close.
    Settlements stay open afterwards so that debt can still be paid off."""
    require_open(group)
    group.archived_at = datetime.now(UTC)
    db.commit()
    db.refresh(group)
    return group


def reopen_group(db: Session, group: Group) -> Group:
    if group.is_open:
        raise ConflictError("This group is not closed")
    group.archived_at = None
    db.commit()
    db.refresh(group)
    return group
```

```python
@router.post("/{group_id}/close", response_model=GroupOut)
def close_group(membership: GroupMembership, db: DbSession) -> GroupOut:
    """End a group without erasing it. A closed group is fully readable and
    takes no new expenses; settlements stay open so outstanding debts can
    still be paid off. Reversible with `/reopen`."""
    group_service.require_owner(membership)
    group = group_service.close_group(db, membership.group)
    return GroupOut.model_validate(group)


@router.post("/{group_id}/reopen", response_model=GroupOut)
def reopen_group(membership: GroupMembership, db: DbSession) -> GroupOut:
    group_service.require_owner(membership)
    group = group_service.reopen_group(db, membership.group)
    return GroupOut.model_validate(group)
```

In `frontend/src/features/groups/api.ts`, after `useDeleteGroup`:

```ts
/**
 * Close a group, and reopen it.
 *
 * Both invalidate the whole `groups` tree rather than one group: closing moves
 * a group between two sections of the list and changes whether the `+` bar
 * offers it, so the list is as stale as the group itself.
 */
export function useCloseGroup() {
  const queryClient = useQueryClient()
  return useMutation({
    mutationFn: (groupId: string) =>
      unwrap<Group>(
        api.POST('/api/groups/{group_id}/close', { params: { path: { group_id: groupId } } }),
      ),
    onSuccess: () => {
      void queryClient.invalidateQueries({ queryKey: qk.groups.all() })
    },
  })
}

export function useReopenGroup() {
  const queryClient = useQueryClient()
  return useMutation({
    mutationFn: (groupId: string) =>
      unwrap<Group>(
        api.POST('/api/groups/{group_id}/reopen', { params: { path: { group_id: groupId } } }),
      ),
    onSuccess: () => {
      void queryClient.invalidateQueries({ queryKey: qk.groups.all() })
    },
  })
}
```

- [ ] **Step 3: Implement**

```ts
/**
 * People you already share a group with.
 *
 * A derivation, not a request: `useGroups()` already caches every group you are
 * in with its full member list, so the server has nothing to tell us that we do
 * not already have. A `GET /users/suggestions` could rank better one day --
 * shared expense recency rather than shared group count -- and that is the day
 * to build it.
 */
export function rankSuggestions(
  groups: Group[],
  meId: string | undefined,
  excludeIds: string[],
): Suggestion[] {
  const excluded = new Set([...excludeIds, ...(meId ? [meId] : [])])
  const counts = new Map<string, { user: User; sharedGroups: number }>()

  for (const group of groups) {
    for (const member of group.members) {
      if (member.left_at !== null) continue
      if (excluded.has(member.user.id)) continue
      const seen = counts.get(member.user.id)
      if (seen) seen.sharedGroups += 1
      else counts.set(member.user.id, { user: member.user, sharedGroups: 1 })
    }
  }

  return [...counts.values()].sort(
    (a, b) => b.sharedGroups - a.sharedGroups || a.user.name.localeCompare(b.user.name),
  )
}

export function useMemberSuggestions(excludeIds: string[]): Suggestion[] {
  const groups = useGroups()
  const { user } = useAuth()
  return useMemo(
    () => rankSuggestions(groups.data ?? [], user?.id, excludeIds),
    [groups.data, user?.id, excludeIds.join(',')],
  )
}
```
