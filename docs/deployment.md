# Deploying StudentWise

Epic 10. How the live app is built, where it runs, how to set it up from zero,
and every production decision with its reason. If something about the live app
surprises you, the answer should be on this page -- and if it is not, add it.

## What runs where

| Piece | Where | Cost |
|---|---|---|
| API **and** frontend, one Docker image | Render free web service, Frankfurt | $0 |
| Postgres 16 | Neon free tier, AWS eu-central-1 (Frankfurt) | $0 |
| Receipt photos | In that Postgres (`receipt_images`) | -- |
| Claude | Our Anthropic key | usage |

The lecturer approved hosting with a $20 total budget (10.1). This setup spends
none of it; the only running cost is Claude.

**One image, one origin.** The frontend calls `/api` on whatever host it was
loaded from, and the service worker caches by that path. So FastAPI serves the
built frontend too (`backend/app/api/frontend.py`): no CORS, no second deploy,
one URL to register with Google. The image is built from the repo root
`Dockerfile`: Node builds `frontend/dist`, a slim Python image serves it.

**Why not Render's own Postgres:** the free one is deleted 30 days after it is
created. Neon's free tier keeps data indefinitely.

**Why receipts are in Postgres:** a free Render service's disk is wiped on every
deploy, restart and spin-down. In development receipts are still files
(`RECEIPT_STORAGE=local`); production defaults to `database`. Same keys, same
code path -- `core/storage.py` has both stores.

## Setting it up from zero

About 30 minutes. Steps 1-2 need a laptop with the backend venv.

### 1. Neon (10.2)

1. <https://neon.tech> → sign up (GitHub login is fine) → **New project**.
2. Name `studentwise`, Postgres **16**, region **AWS Europe Central 1
   (Frankfurt)** -- next to Render's Frankfurt region. Every request makes several
   queries; an ocean between them would add a second to each screen.
3. **Connect** → copy the connection string with **connection pooling off**
   (the host must *not* contain `-pooler`). One small server needs no pooler,
   and Alembic should talk to Postgres directly.

It looks like
`postgresql://neondb_owner:...@ep-xxx-123.eu-central-1.aws.neon.tech/neondb?sslmode=require&channel_binding=require`.
Paste it exactly as shown: the app rewrites `postgresql://` for psycopg, and
`sslmode=require` is what we want.

### 2. Schema and demo data, from your laptop

```powershell
cd backend ; .\.venv\Scripts\Activate.ps1
$env:DATABASE_URL = "<the Neon string>"
alembic upgrade head
python seed.py --wipe=ep-xxx-123.eu-central-1.aws.neon.tech   # the host from the string
python make_readonly_role.py     # prints READONLY_DATABASE_URL=..., keep it for step 3
Remove-Item Env:DATABASE_URL     # don't leave it lying around
```

`make_readonly_role.py` creates the role the AI's generated SQL runs as (see
the review table at the end). Running it again rotates its password.

`seed.py` wipes before it seeds, so against anything but localhost it refuses
until you type the host's name. The live app gets the same demo world as
development: seven accounts, `password123`, sign in as `gal@studentwise.dev`
(see [`testing.md`](testing.md)).

### 3. Render (10.3, 10.5)

Render deploys from GitHub, and **only the repo's owner can grant Render access
to a private repo** -- so the owner (Gal) does this step, or installs Render's
GitHub app on the repo for whoever does.

1. <https://render.com> → sign up with GitHub → **New → Blueprint** → pick
   `StudentWise`. Render reads `render.yaml`.
2. It asks for the `sync: false` values:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | the Neon string from step 1 |
   | `ANTHROPIC_API_KEY` | our key (blank = AI features answer 503, the rest works) |
   | `VOYAGE_API_KEY` | optional: semantic search in the chat (blank = not offered). The Voyage account needs a payment method, or it is limited to 3 requests a minute, and its training opt-out on |
   | `READONLY_DATABASE_URL` | the line `make_readonly_role.py` printed |
   | `TOKEN_ENCRYPTION_KEY`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | blank for now; see *Gmail in production* |

   `JWT_SECRET` is generated by Render and never shown to anyone -- which is the
   point. `ENVIRONMENT=production` is baked into the image, and the public URL
   comes from Render's own `RENDER_EXTERNAL_URL`.
3. **Apply.** The first build takes about five minutes.

### 4. Check it

- `https://<name>.onrender.com/health` → `{"status":"ok"}`
- Sign in as Gal; open Dizengoff 5; reload the page (a deep link must not 404).
- Attach a receipt to an expense, then **Manual Deploy → Restart service** in
  Render and open it again. It must still be there.
- Ask a question on the Ask screen.
- At <https://console.anthropic.com> → **Limits**, set a **monthly spend limit**.
  The demo password is public, so anyone with the URL can sign in and use the
  AI features on our key.

## Everyday

- **Deploying** is merging to `main`. `autoDeployTrigger: checksPass` makes
  Render wait until CI passes, and the CI `image` job builds and boots this
  exact image in production mode -- a broken Dockerfile fails the PR, not the
  deploy.
- **Migrations** run when the container starts (`alembic upgrade head`, then
  uvicorn). Render's pre-deploy command would be cleaner but is a paid feature.
  Render keeps the old instance serving until the new one passes `/health`, so
  a migration that fails leaves the previous version up.
- **Rolling back** the code: Render → Deploys → an earlier deploy → *Rollback*.
  It does not roll the schema back; a migration has to be reversed by hand.
- **Logs**: Render → Logs. A server with a bad setting does not start, and the
  log lists every problem at once (never the values -- see below).

## Gmail in production

Optional; the app runs fine without it. On top of [`gmail-setup.md`](gmail-setup.md):

1. Google Cloud → the OAuth client → **Authorized redirect URIs** → add
   `https://<name>.onrender.com/api/integrations/gmail/callback`.
2. Every Gmail address that will connect must be a **test user** (Testing mode).
3. `python make_secrets.py` → put `TOKEN_ENCRYPTION_KEY` in Render, with
   `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`. The server refuses to start if
   Google is configured without the encryption key.

## Limits worth knowing before a demo

- **The free service sleeps after 15 minutes without traffic** and takes about
  a minute to wake. Open the URL a couple of minutes before presenting.
- Neon suspends its compute after 5 idle minutes; the first query after that
  takes about a second.
- Neon free storage is 0.5 GB. Receipts are capped at 5 MB each, so that is
  around a hundred full-size photos, more for normal phone shots.
- 750 free instance hours a month -- enough for one service running all month.
- Render does not document a short request timeout (unlike Heroku's 30 s). The
  slowest call we make is a chat answer, up to about 60 s; if a proxy is ever
  put in front, give it at least 90 s.

## The production settings review (10.6)

`ENVIRONMENT=production` turns these on. The checks live in
`app/config.py` (`production_problems`) and are tested in
`tests/unit/test_production_settings.py`.

| Concern | Decision | Why |
|---|---|---|
| JWT secret | Refuses to start on the committed dev secret or anything under 32 bytes | The dev secret is in the repo; with it anyone can sign a token for any account |
| Gmail token key | Must be a valid Fernet key; required whenever Google is configured | A bad key would only fail when someone first connects |
| Secrets in error messages | `hide_input_in_errors` | A settings error is printed to the deploy log, and pydantic would echo the database password and API key into it |
| Secrets in the image | `.dockerignore` excludes every `.env`; secrets come only from Render's environment | Anyone who can pull the image would have them |
| CORS | No origins in production; `*` and plain `http://` origins refused | Same origin, so no browser needs a grant |
| HTTPS | Render terminates TLS and redirects HTTP; uvicorn runs with `--proxy-headers` | Otherwise the app believes it is on `http://` |
| HSTS | `max-age=31536000; includeSubDomains`, production only | A browser that has seen us once never tries plain HTTP; on localhost it would outlive the dev server |
| CSP on the app shell | `script-src 'self'` plus the inline theme script's hash, computed from the built `index.html` at startup | No injected script runs; editing the snippet cannot silently break the policy |
| Framing | `X-Frame-Options: DENY`, `frame-ancestors 'none'` | Clickjacking a "settle up" button |
| Sniffing / referrer | `nosniff`, `strict-origin-when-cross-origin` on every response | -- |
| Caching | Fingerprinted assets: a year, immutable. `index.html`, `sw.js`, manifest, icons: `no-cache` | A cached service worker would pin every phone to the old build |
| Database connection | `sslmode=require` from Neon's string; verified TLS 1.3 | -- |
| Container user | Runs as uid 10001, not root | A bug that writes files finds nothing of ours to write to |
| `seed.py` | Refuses a non-local database unless its host is named | It wipes first |
| Generated SQL (Ask, chat) | Runs as `studentwise_readonly`: SELECT on the six tables the SQL guard allows, `users` without `password_hash` (column grants), no writes. Tested by connecting as the role | The fourth layer under the guard, the group scoping and the READ ONLY transaction -- Postgres itself refuses what slipped past them |
| `/docs` | Left on | Graders and teammates use it; every endpoint behind it still needs a token |
| Rate limiting | **Not done** | Known gap: login is not throttled and anyone can register and call the AI endpoints. The Anthropic spend limit is the backstop |
