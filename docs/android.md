# StudentWise on Android (mission 9.12)

The Android app is a **Trusted Web Activity**: a thin Android shell that opens
the live site, https://studentwise-4o6d.onrender.com, full screen in Chrome. It
is the same app as the website and the iPhone home-screen install, so every
deploy updates it at once — the APK only needs rebuilding if the address, the
name or the icon changes.

It was generated by [PWABuilder](https://www.pwabuilder.com) from the live
site's manifest on 2026-10-06.

## Installing it on a phone

The APK is not in the repository — it is a build output, and it is signed with
a key that must not be shared. Dana has it (`StudentWise.apk`); send it to the
phone any way you like (email, Drive, WhatsApp to yourself).

1. On the phone, open the file. Android asks to allow installs **from this
   source** (your browser, Files or Drive) — allow it once.
2. Tap **Install**. Play Protect may say it does not recognise the developer;
   choose **Install anyway**. That is what every app outside the Play Store gets.
3. Open **StudentWise** from the home screen and sign in
   (`gal@studentwise.dev` / `password123` for the demo).

It should open **with no address bar**. If an address bar shows at the top,
Android could not verify that the app and the site belong together — see below.

Chrome must be installed and up to date; the app runs inside it.

## Why there is no address bar: `assetlinks.json`

Android shows the app full screen only after checking that the site vouches
for it. The site does that at
https://studentwise-4o6d.onrender.com/.well-known/assetlinks.json, which names
the package and the SHA-256 fingerprint of the key the APK was signed with
(`frontend/public/.well-known/assetlinks.json`, served by the backend like any
built file; `tests/api/test_frontend.py` checks both).

- **If the site moves** (a custom domain, a new Render service), the APK has to
  be rebuilt for the new address, and the file must be served there too.
- **If the app goes on Google Play**, Play re-signs it with its own key. Add
  Play's fingerprint (Play Console → Setup → App signing) to
  `sha256_cert_fingerprints` *alongside* this one, or the Play version opens
  with an address bar.

Google's own checker says whether the file is right:
`https://digitalassetlinks.googleapis.com/v1/statements:list?source.web.site=https://studentwise-4o6d.onrender.com&relation=delegate_permission/common.handle_all_urls`

## The signing key

`signing.keystore` and `signing-key-info.txt` (its passwords) are kept **outside
every repository**, on Dana's machine in `StudentWise-android-signing/`.

- **Back them up somewhere private** — a password manager or a private drive.
- **Never commit them.** Anyone with the key can publish an "update" that
  Android accepts as this app.
- **Without them, the app can never be updated** under this package id: a new
  key means a new app, and everyone reinstalls.

## Rebuilding it

Only needed for a new address, name, icon or version.

1. https://www.pwabuilder.com → enter the live address → **Package for stores**
   → **Android**.
2. Package id `dev.studentwise.app`; raise the version and version code.
3. Signing key: **Use mine**, and upload `signing.keystore` with the alias
   `studentwise` and the passwords from `signing-key-info.txt`. A *new* key
   would change the fingerprint and break `assetlinks.json`.
4. Download, and install the new `.apk` over the old one.

The `.aab` in the same download is what Google Play wants, if the app is ever
published there.

## How it was tested (2026-10-06)

- **The signature:** `keytool -printcert -jarfile StudentWise.apk` gives the
  fingerprint in `assetlinks.json` exactly, and the keystore opens with the
  passwords in `signing-key-info.txt` (valid to 2081).
- **Serving the file:** the backend returns `/.well-known/assetlinks.json` as a
  200, `application/json`, no redirect — against a real `npm run build`, and in
  `tests/api/test_frontend.py`.
- **On Android 14** (the SDK emulator, a Pixel 7 image with Google Play): the
  APK installs as `dev.studentwise.app` 1.0.0.0, opens on its splash screen and
  loads the live site. Before `assetlinks.json` is live it shows an address
  bar, as expected; with Chrome told to treat the site as verified — exactly
  what the deployed file does — it runs **full screen**, and signing in as Gal
  shows the real Home screen from production.
- The emulator's built-in Chrome 113 crashes in its GPU compositor under the
  default emulated graphics; `-gpu guest` avoids it. That is the emulator, not
  the app — but **one install on a real Android phone** after this is deployed
  is still the check that counts.
