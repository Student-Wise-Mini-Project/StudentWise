# 2026-09-11 — The frontend, and six bugs that only showed up under test

Missions attempted: **9.1, 9.2, 9.3, 9.4, 9.5, 9.6, 9.7, 9.11**. All eight landed.

Result: **121 frontend tests**, lint, typecheck and build green, and an app you
can sign into, use, and install on an iPhone home screen.

Epic 9 goes from 0/12 to 8/12. What is left — charts, the Ask screen, anomaly
alerts, the APK — are additions on top of a working app rather than parts of one.

---

## The three seams that shaped everything

**1. Types are generated, never written.** `src/api/schema.d.ts` comes from
`openapi-typescript` reading the backend's own schema, and a `contract` CI job
regenerates it from `app.main` and fails on a diff. It is the frontend's
`alembic check`, and it paid for itself immediately: `ExpenseOut` carries a
`split_rule` field that `docs/api-contract.md` never mentioned. A hand-written
client would have encoded that gap permanently. The doc is now fixed.

**2. Only one file may name a colour.** Every visual value lives in
`src/styles/theme.css`, and `test/guards/design-tokens.test.ts` fails the build
on a hex, an `rgb(`, a `font-family` or a Tailwind arbitrary-colour class
anywhere else. This is the whole reason the Claude Design output (brief at
`docs/design-brief.md`) can be applied as a one-file edit rather than a rewrite.
Both guards were verified to fail before being trusted: a probe with `#ff0000`,
`bg-[#123456]`, `ml-4` and `text-left` tripped four of them.

**3. The client never divides money.** The contract says "never re-derive splits
on the client" and this keeps it literally. `lib/money.ts` exposes no function
that splits a total between people. The single division, `divideForDisplay`,
returns `{ value, approximate: true }` — so the only thing that can render it is
`<Money approximate />`, and the `≈` is enforced by the type system rather than
by a reviewer noticing its absence. In the split editor, percentages and weights
show **no money at all**: either could be turned into an amount with one
multiplication, and that amount would be right for most people and a cent out for
one — and the one who is out is the one who checks.

## What surprised us

### Every request through the typed client was broken

`env.API_URL` defaulted to `''` so the app would be same-origin behind the Vite
proxy. But `openapi-fetch` builds a `new URL()` internally, and
`new URL('/api/auth/me', '')` throws `Invalid URL` — it does not fall back to a
relative request. Nothing using the generated client would have worked in a
browser either.

Worse, a `catch` that existed to let the 401 middleware handle dead tokens
swallowed the `TypeError` too, so the only symptom was a session that never
resolved. Both are fixed; the catch now logs in development.

### `openapi-fetch` captures `globalThis.fetch` at client creation

Which is at module import — earlier than anything that replaces `fetch`
afterwards. In tests that is MSW, so interception applied to every plain `fetch`
and silently not to the typed client, and the symptom looked exactly like a bad
handler pattern. The client now resolves `fetch` per call. The same trap would
catch any runtime instrumentation of `fetch` in production.

### jsdom made every typed request fail before it was sent

TanStack Query passes an `AbortSignal` to every query function. jsdom installs
its own `AbortController`, and once MSW patches the global `Request`, the brand
check in `new Request(url, { signal })` fails with *"Expected signal to be an
instance of AbortSignal"*. The alternative to fixing the environment was to stop
forwarding the signal — dropping request cancellation from the real app to
satisfy a test. Switched to `happy-dom` instead.

### A lint rule that was catching nothing

`no-restricted-globals` does not match `window.localStorage`, only the bare
identifier. The rule fencing off the auth token's storage had been inert since it
was written. Replaced with `no-restricted-properties` covering both forms, and
verified against a probe file.

### `1,234.50` parsed to nothing

Treating a comma as always a decimal separator turned it into `1.234.50`, which
is not a number, so the amount field silently emptied itself while somebody was
typing rent. Separators are now resolved by position — whichever appears last is
the decimal one — with a guard so `0.500` stays half a shekel rather than
becoming five hundred.

### A route that matched nothing

`/expenses/:id/edit` fell through to Not Found, which looks exactly like a
deleted expense rather than a broken link. Expense links are now group-scoped and
the flat path survives only as a redirect, for the activity feed and
notifications which link to an expense without knowing its group. A test now
walks every route a link points at.

### The backend on :8000 was two epics out of date

Serving **15 paths against a codebase of 40** — a uvicorn started before Epic 2
landed and never restarted. Every "missing endpoint" chased for twenty minutes
was that. Worth remembering next time an endpoint is mysteriously absent.

### One commit went in red

The PWA commit had two lint errors, because the verification command chained on
the build result rather than on lint. Fixed in the commit after it, and recorded
here rather than quietly amended.

## Decisions worth recording

- **Tailwind v4 specifically**, because v4 moved configuration into CSS `@theme`
  blocks — the token file *is* the config, which is exactly the retheme seam
  needed. v3's JS config would have split tokens across two files.
- **Rubik and Assistant** as the typefaces, because both ship full Hebrew
  alongside Latin. The app is English now and Hebrew later; a Latin-only face
  would have meant choosing twice.
- **English UI, RTL-ready** rather than full i18n. Direction is a layout problem
  that logical CSS properties solve and a test enforces; translation is a
  separate axis, and routing every label through `t('...')` before anyone needs a
  second language buys indirection rather than readiness.
- **Infinite scroll, not numbered pages.** `has_more ? offset + limit : undefined`
  is the whole adapter, and `total` is still there for an honest "18 expenses"
  header. A page-number control is a poor fit for a thumb.
- **One invalidation helper.** Anything that writes money invalidates expenses,
  balances, plan, activity and the unread count together. Scattering those across
  nine mutations is how a balances screen ends up disagreeing with the expense
  list beside it.
- **`localStorage` for the token**, deliberately. `sessionStorage` would sign you
  out every time the PWA relaunches from the home screen, which is the main way
  this app is meant to open. The cost is XSS readability, mitigated by a lint
  rule banning `dangerouslySetInnerHTML` and by a one-week token.
- **Signing out clears the API caches.** `NetworkFirst` keeps authenticated
  responses in Cache Storage unencrypted; on a shared laptop that is the previous
  user's expenses. Also cleared when a *different* user signs in.
- **The update is a prompt, not an auto-reload.** A service worker that swaps the
  app out mid-form is worse than a version one refresh out of date.
- **No install button on iOS, because there cannot be one.**
  `beforeinstallprompt` does not fire in Safari. The hint says where the system
  control is, once, and can be dismissed. Detection is its own tested module
  because **an iPad reports itself as `Macintosh; Intel Mac OS X`** and only the
  touch-point count separates it from a desktop Mac.
- **Home totals per currency and never sums them.** Groups can be in different
  currencies and the backend refuses to convert; adding shekels to euros here
  would invent an exchange rate the rest of the app is careful not to have.

## Next

   Applying the result should touch `src/styles/theme.css` and `src/components/`
   and nothing else — if it touches a screen, the token system failed and that is
   worth knowing.
2. **9.8, 9.9, 9.10** — charts, the Ask screen, anomaly alerts. All three are new
   screens against endpoints that already exist, and all three are Dana's.
3. **10.1** — still the question that gates all of deployment.

Two things noticed and deliberately not done:

- The home screen's "you are owed" figure fans out one balances request per
  group. Fine for a handful of groups, wrong for fifty. The fix is one endpoint,
  not a client change, and it is not needed yet.
- `useUnreadCount` does not poll. There is no push channel, and asking every few
  seconds whether nothing has happened is a battery cost paid by a phone in
  somebody's pocket. It refreshes on focus instead.
