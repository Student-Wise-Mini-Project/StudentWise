# 2026-09-12 — Hebrew, and the i18n layer under it

Mission 9.13. The app runs in Hebrew and English, switchable per device, with
the document direction flipping with it.

Branch: `feat/i18n-hebrew`, stacked on `feat/kiosk-identity`.

## What was built

`src/i18n/` — about 150 lines and no new dependency. JSON catalogues in ten
namespaces, a React context, `{name}` interpolation, and `Intl.PluralRules`.
Every screen, every shared component, every error message and all seven
notification kinds.

The language lives in `lib/prefs.ts` beside the theme — per device, not per
account, kept when you sign out — and `index.html` stamps it before first paint
by the same inline script that already did that for the theme.

## Decisions, and how they held up

**A typed `t()` rather than i18next.** The argument was never bundle size; it
was that keys derived from the English catalogue make a typo and a missing
Hebrew string both compile errors, which a library only approximates through
hand-written module augmentation.

It held, and we checked rather than assumed: deleting `he.common.actions.cancel`
made `tsc` report `Property 'cancel' is missing`. That check is also what found
the broken typecheck script (below).

**Notification wording moved to the client.** It was rendered in Python and
arrived already-worded, so a frontend-only translation would have left the
Alerts screen in English. No backend change was needed, because
`NotificationOut` has shipped `payload` since the first version and its
docstring says why: *"so a client that wants to write its own wording (in
Hebrew, say) never has to parse English."* `features/notifications/render.ts` is
a direct port of `notification_service.render()`, with the server's English kept
as the fallback for a `kind` the client does not know — so the kinds Epic 5 adds
degrade to English rather than to a blank row.

**Gender-neutral Hebrew.** The API stores no gender for a user and should not
start. Every string is phrased so the question does not arise: `החוב שלך` rather
than `אתה חייב`, `בתשלום גל` rather than `גל שילם`. Past-tense second person
(`שילמת`, `הוספת`, `הלווית`) is spelled identically for both genders and carried
a lot of the weight. This is the one rule no test can enforce, so it is written
down in CLAUDE.md and in `frontend/README.md`.

**Detect, fall back to Hebrew.** The audience is Israeli students paying in ₪
through Bit and PayBox.

## Three things that surprised us

**`npm run typecheck` had never checked anything.** It was `tsc --noEmit`
pointed at `tsconfig.json`, which is a solution file with `"files": []` and two
references. `tsc --noEmit` against a solution file typechecks nothing and exits
0 — so the script, and the `typecheck` step in CI at `ci.yml:89`, had been
passing regardless of what was in `src/`. Only `npm run build`'s `tsc -b` was
catching anything. Fixed to `tsc -b`, verified in both directions.

It was found by trying to *prove* the type guarantee rather than assuming it.
That is the whole lesson: the check we ran to test a claim turned out to
invalidate the tool we were testing it with.

**The guard found seventeen strings the translation pass had missed** — and one
file, `pwa/PwaPrompts.tsx`, that appeared in the plan's coverage list and was
never assigned to a task at all.

Most of the seventeen were one shape. A button label inside a multi-line element
sits on a line of its own, so a `>text<` pattern — which needs both angle
brackets on the same line — never sees it. That is the commonest shape a label
takes. Writing the guard *after* the translation rather than before is what made
this visible; written first, it would have been tuned against noise and probably
written without that second check.

**`lower()` is gone.** It lowercased a sentence's first letter so it could be
spliced in after the word "Then". Hebrew has no letter case, and once "Then"
moved into the key the English did not need it either.

## What got better on the way past

- `splitValidation` returns a `MessageKey` instead of a sentence, so its 18
  tests no longer break when copy is reworded — but do break if a key
  disappears. Strictly better, and a side effect rather than a goal.
- Two unrelated fixes that were sitting uncommitted in the tree got committed
  first, separately, so the i18n commits contain only i18n: the add-expense bar
  now reads the route it is on, and the new-expense form defaults the payer to
  the signed-in user rather than `members[0]`.

## What is next

- **9.9** the Ask screen, **9.10** anomaly alerts, **9.12** the APK.
- Backend `Accept-Language`. Not needed while a client is in the room; needed
  the day notifications are emailed or pushed.
- The PWA manifest and the `index.html` meta description are still English only.
  The manifest is generated at build time from one config and would need a build
  step to vary by locale.
- Nobody but Gal reads Hebrew as a reviewer of record. The neutral-phrasing rule
  is the part most likely to erode, and it erodes silently.
